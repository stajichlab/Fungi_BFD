## `results/genome_stats_by_name/` and `results/function_by_name/`

**Regenerable derived views — never a source of truth.** These are read-only
symlink trees, generated by `scripts/build_genome_stats_by_name_symlinks.py`,
that mirror the hash-bucketed canonical stores (`results/genome_stats/*`,
`results/function/*` — see `todo/genome_stats_storage_reorg.md` T-014) under
a human-browsable `<GENUS-or-NOGENUS>/<Genus_species_strain>.<type>.<ext>`
layout, for anyone who wants to browse or `ls` by species name rather than by
hash bucket. Every entry is a relative symlink into the real canonical file;
nothing under `*_by_name/` is ever written to directly.

**Regenerate with**: `python3 scripts/build_genome_stats_by_name_symlinks.py`
(no-op if nothing changed since the last run — see the script's own
docstring for the staleness-check mechanics and a documented limitation).
Full rebuild every time it does run (never an incremental diff), so it's
always safe to delete `results/genome_stats_by_name/` /
`results/function_by_name/` outright and regenerate from scratch.

**Exclude from backup/rsync/tar passes over `results/`.** Because every leaf
is a symlink, a backup tool that follows symlinks by default (rather than
copying the symlink itself) would needlessly re-touch/re-copy every target
file a second time under `*_by_name/`'s tree — pure waste, since the
directory is fully regenerable from `samples.csv` + the canonical store in a
single script run. If backing up `results/` with `rsync`, add
`--exclude='*_by_name/'` (or equivalent for whatever tool is in use).
